# 백년건강소 블로그

단일 랜딩을 홈·게시판·여러 글 상세·편집실로 확장한 정적 블로그입니다. 요청에 따라 GitHub 소스만 관리하며 공개 배포는 아직 하지 않았습니다.

## 열기

프로젝트 폴더의 터미널에서:

```powershell
python -m http.server 8080 --bind 127.0.0.1
```

- 홈: http://127.0.0.1:8080/
- 게시판: http://127.0.0.1:8080/board.html
- 글: http://127.0.0.1:8080/post.html?post=cabbage-story
- 편집실: http://127.0.0.1:8080/editor.html
- 종료: Ctrl+C

파일 더블클릭으로도 확인할 수 있습니다. 미리보기·브라우저 저장·클립보드는 로컬 서버에서 사용하는 것을 권장합니다.

## 블로그 구조

| 파일 | 역할 |
| --- | --- |
| index.html / css/home.css / js/home.js | 홈 배너·공지·인기글·최신글·프로필·태그 검색 |
| board.html / js/blog-board.js | 전체글·인기글·자유게시판·후기·공지, 검색·더보기 |
| post.html / js/app.js | 글 상세·제품 링크·하단 메뉴·댓글 영역 |
| editor.html / js/editor.js | 글 추가·수정·삭제·분류, 블로그 홈 설정, 초안·파일 저장 |
| blog-data.js | 블로그 설정과 모든 글 데이터 — 이 파일을 주로 편집합니다 |
| content.js | 이전 랜딩 설정과 새 글 기본값, 기존 파일 가져오기 지원 |
| assets/images/ | 게시글 사진과 배너 사진 |

주소는 `index.html`이 홈, `post.html?post=글ID`가 상세입니다. 예전 `index.html#comments`는 기본 글의 댓글 위치로 이동하도록 호환 처리했습니다. 기존 광고 URL을 운영 중이라면 실제 배포 전에 상세 주소로 수정하세요.

## 글을 여러 편 등록하기

1. 편집실에서 **+ 새 글**을 누릅니다.
2. 주소 ID를 영문 소문자·숫자·하이픈으로 입력합니다. 예: `cabbage-story`, `daily-note-01`. 글마다 달라야 하며, 배포 후에는 기존 링크가 유지되도록 가급적 변경하지 않습니다.
3. 게시판·제목·작성자·날짜·설명·키워드를 입력합니다.
4. **글 한번에 넣기**로 원고를 붙이고, 문단·소제목·이미지 블록을 추가합니다. ↑↓로 순서를 바꿉니다.
5. 공개 설정을 켜면 홈과 게시판에 표시됩니다. 새 글은 기본 비공개입니다.
6. 운영자 선정 글은 **인기글에 선정**을 켭니다. 실제 조회수 순위나 방문자 추천 수가 아닙니다.
7. 구매 영역이 필요한 글만 **글 아래 제품 구매 영역 표시**를 켜세요.
8. **blog-data.js 다운로드**를 누르고 프로젝트의 기존 파일을 덮어쓴 뒤 GitHub에 업로드·배포합니다.

글 선택기로 다른 글을 편집해도 현재 수정 내용은 다운로드 전까지 편집 화면 메모리에 남습니다. 페이지를 닫기 전 전체 초안 저장 또는 파일 다운로드를 하세요. 초안 저장은 현재 브라우저에만 저장하며, GitHub나 서버에 업로드하는 기능이 아닙니다.

비공개 글은 목록·직접 URL에서 숨기지만 정적 데이터 파일에는 포함됩니다. 접근 제어가 아니므로 비밀번호·개인정보 등 민감한 내용은 저장하지 마세요. 편집실 자체도 서버 로그인 보호가 없습니다. 타인이 공개 편집실에서 변경해도 서버의 파일을 쓸 수 없으므로 다운로드/배포 전에는 공개 페이지에 반영되지 않습니다.

## 홈 배너와 프로필 바꾸기

편집실의 **블로그 홈 설정**을 펼쳐 이름·소개·배너 제목·대표 사진 경로를 입력합니다. 대표 사진이 비어 있으면 기본 잎 일러스트가 표시됩니다. 글과 홈 설정은 모두 blog-data.js에 저장됩니다. 편집실 오른쪽은 선택한 글의 미리보기이며 홈 설정은 파일을 저장한 뒤 홈을 새로고침해 확인하세요.

## 이미지 넣기

- 사진을 `assets/images/product-01.jpg`처럼 폴더에 넣고 이미지 블록에 그 경로를 적습니다.
- 내 PC 이미지 선택 기능은 영문 파일명 사본을 다운로드합니다. 해당 파일을 반드시 assets/images 폴더에 옮겨야 표시됩니다. 서버 자동 업로드가 아닙니다.
- 공개 HTTPS 이미지 URL도 사용할 수 있습니다. 웹페이지 URL 대신 이미지 자체 주소를 넣어야 합니다. 로그인이나 외부 참조 제한이 있는 주소는 작동하지 않을 수 있습니다.
- 목록 썸네일을 지정하지 않으면 본문의 첫 이미지가 사용됩니다. 그것도 없으면 기본 자리표시자가 표시됩니다.
- JPG/PNG/WebP/GIF를 사용할 수 있습니다. 파일명을 영문·숫자·하이픈으로 만들면 관리하기 쉽습니다.

## 랜딩 URL과 구매 URL

```text
광고 → https://도메인/post.html?post=cabbage-story → 글의 구매 버튼 → 실제 상품 판매 페이지
```

- 블로그 홈 URL은 `https://도메인/`입니다.
- 글의 랜딩 URL은 `https://도메인/post.html?post=글ID`입니다. 편집실에서 글마다 지정할 수 있습니다.
- 구매 URL은 스마트스토어·자사몰 등 상품 판매 페이지입니다. 비어 있으면 구매 버튼은 비활성화됩니다.
- URL 입력만으로 도메인이나 사이트가 생성되지는 않습니다. 먼저 호스팅에 배포해야 합니다.
- `#comments`를 글 주소 끝에 붙이면 댓글 위치로 이동합니다.

## UTM 설정

편집실에서 선택한 글의 랜딩 URL을 입력하고 UTM 생성기를 사용합니다. 이미 `?post=...`가 있어도 나머지 매개변수를 올바르게 덧붙입니다.

```text
https://your-domain.example/post.html?post=cabbage-story&utm_source=instagram&utm_medium=paid_social&utm_campaign=cabbage_stick_202611&utm_content=story_01
```

| 항목 | 의미 | 예 |
| --- | --- | --- |
| utm_source | 플랫폼 | instagram |
| utm_medium | 유입 매체 | paid_social |
| utm_campaign | 캠페인 | cabbage_stick_202611 |
| utm_content | 소재 | story_01 |
| utm_term | 키워드, 선택 | cabbage |
| utm_id | 캠페인 ID, 선택 | campaign_01 |

전체 URL을 광고의 도착 URL에 넣으세요. 플랫폼에서 매개변수 입력란을 별도로 쓰는 경우 중복 입력하지 마세요. UTM은 주소 정보일 뿐 통계 저장 도구는 아닙니다.

UTM 구매 링크 전달 옵션을 켜면 위 6종만 전달하며 구매 URL의 기존 UTM·상품 코드·앵커는 보존합니다. gclid/fbclid는 전달하지 않습니다. 같은 GA4 속성으로 도메인 간 측정을 구성한다면 UTM 재전달을 끄고 도메인 간 측정을 별도 설정하세요.

글의 본인 GA4 측정 ID에 G-...를 입력하면 해당 글의 Google 태그가 작동합니다. 편집실 미리보기는 추적하지 않습니다. 구매 버튼은 purchase_link_click 이벤트를 전송하며 구매 완료 측정은 아닙니다. 홈 방문 추적·결제 완료 추적·분석 계정·동의 관리는 아직 구성하지 않았습니다.

## 배포와 도메인 (추후)

Cloudflare Pages 등 정적 호스팅에 이 폴더를 배포할 수 있습니다. Cloudflare Git 연동을 사용한다면 저장소 hlchoyrcompany-max/-, 브랜치 main, 프레임워크 없음, 빌드 명령이 필요하면 exit 0, 출력 폴더는 루트(.)를 선택합니다. 배포 결과의 실제 pages.dev 주소를 사용하고, 보유 도메인은 Custom domains 안내에 따라 연결하세요.

편집실 파일은 공개 배포에서 제외해도 됩니다. blog-data.js·content.js·본문 스크립트와 CSS는 포함해야 합니다. 공유 미리보기는 초기 HTML만 읽는 로봇이 있으므로 배포 시 index.html과 post.html의 title/og 태그를 점검하세요. 글별 검색 노출과 공유 미리보기까지 완전히 지원하려면 정적 글별 HTML 생성 또는 서버 렌더링을 추가해야 합니다.

## 현재 범위

홈·게시판·공개 글 목록·검색·키워드·여러 글 편집·공유·제품 링크·UTM을 구현했습니다. 공개 배포와 서버 댓글·회원가입·인증된 관리자·자동 파일 업로드는 구현하지 않았습니다. 댓글 메뉴는 글 하단 댓글 영역으로 이동합니다. 지정한 네이버 카페 본문은 확보하지 못해 원고 자리표시자를 유지했습니다. 현재 글과 사진이 실제 후기나 실제 제품 사진인 것처럼 꾸미지 않았습니다.

상세의 common/main/blog CSS는 처음 제공한 공개 페이지에서 내려받은 원본에 기반하며, 홈과 블로그 데이터/편집 기능은 새로 구현했습니다. 원본 서버 코드는 포함되지 않습니다.
